## 4. 根因分析

- **DRAFT-LOC-OOB 标记 = 0**：`3c68f20891` 修复链（draft loc source/read-side/CHOKEPOINT 三层
  global→local）已阻止已知的 draft loc 越界路径——**本次是另一条写越界源**。
- **崩溃前兆一致**：accept rate 从健康（0.55-0.76）恶化到 0.01 持续 ~30s 后崩溃 ——
  draft KV 写/读内容污染特征（EAGLE 家族），但具体越界 kernel 未被现有插桩捕获。
- **最可疑：修复仅覆盖 non-DCP 分支**。`3c68f20891` commit message 明言
  "_repair_global_kv_slots_ applied at the gather chokepoint (4 call sites,
  non-DCP branches only — DCP localizes separately)"。decode 是 **DCP=8**，
  若 DCP 分片路径下存在同类 KV slot 语义错误（global 虚拟 slot 泄漏进 DCP 本地表），
  会以不同捕获点复现。
- 排除：KV 传输风暴（#transfer-req: 0）、KV 池满（usage 0.02）、LoRA 触发
  （崩溃前无 expand/shrink 新记录）、seq_lens 负值（已由 44b6f429df 钳制）。

## 5. 后续排查建议

1. 对照 `3c68f20891` 的 non-DCP 修复点，审计 DCP=8 分支（`dcp_enabled()` 路径）
   下 draft/target KV 的 slot 语义（global→local 是否同样需要）。
2. 重启 decode 时带诊断 env：`SGLANG_DSA_STAGE_SYNC=1`、`SGLANG_DEBUG_ALLOC=1`，
   抓崩溃前最后写越界的 kernel 指纹。
3. 若需临时止血：EAGLE kill-switch（44b6f429df 内置）或关 DCP 验证是否为 DCP 路径独有。
