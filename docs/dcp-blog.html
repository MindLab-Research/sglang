设 Prefill 端有 $N_{cp}$ 个 CP rank，Decode 端有 $N_{dcp}$ 个 DCP rank。每个 Prefill CP rank $r$ 持有层集合 $\mathcal{L}_r \subset \{0, \ldots, 77\}$ 和全部 pages $\mathcal{P}_{\text{full}}$。每个 Decode DCP rank $d$ 持有 page 子集 $\mathcal{P}_d = \{p \mid p \bmod N_{dcp} = d\}$ 和全部层。传输目标：对每条路径 $(r, d)$，将 $\mathcal{L}_r \times \mathcal{P}_d$ 的 KV 从 Prefill rank $r$ 传输到 Decode rank $d$。

2D Reshard Target
$$\forall r \in [0, N_{cp}), \; \forall d \in [0, N_{dcp}): \quad \text{Transfer}(\mathcal{L}_r, \; \mathcal{P}_d, \; r \to d)$$

4. CP Layer-Split (Prefill Side)

4.1 Layer Assignment

78 层 Transformer 按 CP rank 连续分块。$\lfloor 78/8 \rfloor = 9$，余数 $78 \bmod 8 = 6$，前 6 个 rank 各分 10 层（$9+1$），后 2 个 rank 各 9 层：

Layer Range
$$\mathcal{L}_r = \left[ r \cdot \left\lceil \frac{L}{N_{cp}} \right\rceil, \;\; (r+1) \cdot \left\lceil \frac{L}{N_{cp}} \right\rceil \right), \quad r = 0, \ldots, N_{cp}-1$$
# Layer assignment: 78 layers → 4 CP ranks function cp_layersplit_layer_range(N_layers, N_cp, r): per ← N_layers div N_cp # 78 / 8 = 9 (remainder 6) return [r × per, (r+1) × per) # half-open interval # Result: # Rank 0: L[0, 10) → 10 layers # Rank 1: L[10, 20) → 10 layers # Rank 2: L[20, 30) → 10 layers # Rank 3: L[30, 40) → 10 layers # Rank 4: L[40, 50) → 10 layers # Rank 5: L[50, 60) → 10 layers # Rank 6: L[60, 69) → 9 layers (remainder) # Rank 7: L[69, 78) → 9 layers (remainder) # KV pool: per+1 slots per rank (owned layers + 1 transient for broadcast) function local_layer_count(N_layers, N_cp, r): [start, end) ← cp_layersplit_layer_range(N_layers, N_cp, r) return (end - start) + 1 # +1 = transient slot

4.2 Prefix KV Broadcast: Size-Broadcast Protocol

非 owner rank 需要从 owner rank 获取 prefix KV。HiCache local-only prefetch 使每 rank 的 prefix 长度可能不同。Size-broadcast 协议确保所有 rank 参与相同数量的 NCCL broadcast：

Size-Broadcast Protocol
$$n = |\text{slots}_{\text{owner}}| \quad \text{(broadcast } n \text{ to all ranks first)}$$ $$\text{if } n = 0: \;\; \forall r: \text{skip} \quad (\text{consistent})$$ $$\text{if } n > 0: \;\; \forall r: \text{broadcast } n \text{ KV elements} \quad (\text{all ranks participate})$$
function broadcast_owner_layer_prefix(layer_id, forward_batch, kind): owner ← cp_layersplit_owner_rank(layer_id, ...) prefix_lens ← forward_batch.extend_prefix_lens_cpu # None guard: normalize to zeros (prevent per-rank None divergence) if prefix_lens = None: prefix_lens ← zeros(len(req_pool_indices)) # Step 1: compute element count count ← |prefix_slots| # Step 2: broadcast count to ALL ranks (1-element, mandatory) n_tensor ← tensor([count]) broadcast(n_tensor, src=owner, group=cp_group) n ← n_tensor.item() # Step 3: consistent skip or consistent broadcast if n = 0: return # ALL ranks skip # Step 4-5: broadcast n KV elements; non-owner writes to transient_pool

5. DCP (Decode Side)

5.1 Page-Level Round-Robin Sharding

Decode 端 KV cache 以 page（64 tokens）为单位按 round-robin 分配。DCP allocator 大小为 $M \times N_{dcp}$（virtual slots），每个 DCP rank 持有 $1/N_{dcp}$ 的 pages：

DCP Page Ownership
$$\text{owner}(p) = p \bmod N_{dcp}, \quad p \in \{0, \ldots, M \cdot N_{dcp} - 1\}$$ $$\text{slot}_{\text{local}}(p) = \left\lfloor \frac{p}{N_{dcp}} \right\rfloor \in \{0, \ldots, M - 1\}$$

5.2 DCP Attention: All-Gather + LSE Merge

每个 DCP rank 只持有 $1/N_{dcp}$ 的 KV pages，attention 输出需要 all-gather + LSE merge 合并：

DCP Attention Output Correction
$$O_{\text{full}} = \text{AllGather}(O_{\text{local}}) \quad \text{(concat along seq dim)}$$ $$\text{LSE}_{\text{merged}} = \log\!\left(\sum_{d=0}^{N_{dcp}-1} \exp(\text{LSE}_d)\right) \quad \text{(merge across DCP ranks)}$$

5.3 Communication Overhead Analysis

DCP introduces two sources of communication overhead per decode step:

Overhead Breakdown (DCP=4, TP=8, 78 layers)

OperationFrequencyVolume per stepImpact
All-gather KVPer attention layer~78 × (hidden_dim × seq_len / N_dcp) bytes~3× extra KV read vs DCP=1
LSE mergePer attention layerN_dcp scalars (negligible)O(N_dcp) all-reduce
PD transfer (2D reshard)Per request (prefill→decode)Full KV × 1/N_dcp pages per path32 paths (8 CP × 4 DCP), parallel via mooncake RDMA

The 32 PD transfer paths execute in parallel—each Prefill CP rank independently sends to each Decode DCP rank via mooncake RDMA, so transfer latency ≈ single-path latency (not 32×). The dominant overhead is the per-step all-gather in DCP attention, which grows linearly with N_dcp but is amortized by EAGLE's speculative decoding (5 steps × 6 draft tokens = 30 tokens verified per step, with accept rate ~39% reducing effective decode steps).

TTFT impact: PD disaggregation adds one RTT for KV transfer (mooncake RDMA, ~0.5-2ms for typical 4K-32K token sequences). The 2D reshard adds page-level filtering overhead (~0.1ms for 256 pages × 4 DCP ranks), negligible compared to prefill compute time. Measured TTFT on B300: 0.38s (DCP=4, 1K input) to 1.7s (DCP=4, 32K input), dominated by prefill compute, not transfer.

6. Page-Level 2D Resharding (Core)

6.1 Page Index Filter

这是 2D reshard 的核心。Prefill 端在 RDMA 发送前，对每层的 page indices 执行 DCP 过滤：

filter_kv_indices_for_dcp_rank
$$\text{mask}(p, d) = \mathbb{1}\!\left[p \bmod N_{dcp} = d\right]$$ $$\text{filtered}(p, d) = \left\lfloor \frac{p}{N_{dcp}} \right\rfloor \quad \text{(compress to local slot)}$$ $$\mathcal{P}_{r \to d} = \left\{ \left\lfloor \frac{p}{N_{dcp}} \right\rfloor \;\middle|\; p \in \mathcal{P}_{\text{full}}, \; p \bmod N_{dcp} = d \right\}$$
# Input: kv_indices = prefill-side global logical page indices (full set) # Output: only pages owned by DCP rank d, mapped to local physical slots function filter_kv_indices_for_dcp_rank(kv_indices, N_dcp, d): if N_dcp ≤ 1: return kv_indices mask ← kv_indices mod N_dcp = d # page ownership test return kv_indices[mask] div N_dcp # compress to local slot
正确性保证：
① kv_indices 是 prefill 端的全局逻辑 page indices（slot = pos，DCP allocator 大小 = $M \times N_{dcp}$）
② mask = page_idx % N_dcp == d：只保留属于目标 decode rank 的 pages
③ // N_dcp：将全局 page slot 压缩为 decode 端的 local physical page slot
④ RDMA write 直接写入 decode 的 DCP 分片布局，无需后处理

6.2 Mooncake Transfer with DCP Reshard

在 mooncake connector 的传输 worker 循环中，每个 TransferInfo 携带目标 decode rank 的 $N_{dcp}$ 和 $d$。Prefill 对每个 layer 的 page indices 执行 DCP 过滤后发送：

# mooncake/conn.py — transfer worker loop (per layer, per TransferInfo) N_dcp ← req.dcp_size # from bootstrap metadata d ← req.dcp_rank # = decode tp_rank % N_dcp if N_dcp > 1: # DCP reshard: filter by decode-side page VALUE parity mask ← dst_indices mod N_dcp = d transfer_indices ← transfer_indices[mask] dst_indices ← (dst_indices[mask] div N_dcp).astype(int32) # Log: [DCP-XFER] pages: 256→64 (1/4 of full sequence) # RDMA write: src=prefill_kv[owned_layer][transfer_indices] # dst=decode_kv[local_slot][dst_indices] send_kvcache(session_id, transfer_blocks)

Page Size Selection

6.5 CP Layer-Split 与 DCP 传输的交互

CP layer-split 下，每个 prefill CP rank 独立发送自己 owned layers 的 KV——不需要跨 CP rank 协调层维度。CP index filtering 在 layer-split 模式下被禁用：

CP Index Filtering Decision
$$F_{cp} = \begin{cases} \text{False} & \text{if layer-split or } N_{cp} > 1 \\ \text{True} & \text{if pure TP (} N_{cp} = 1\text{)} \end{cases}$$

8. EAGLE + DCP Adaptation

EAGLE speculative decoding introduces a draft model that runs in the same process as the target model. The target KV pool is DCP-sharded (each rank holds 1/N_dcp of pages), but the draft model needs the full sequence to generate draft tokens. This creates a fundamental tension:

  • Target model: runs under DCP, sees only 1/N_dcp of KV pages, uses all-gather + LSE merge for attention output.
  • Draft model: must see the full KV to predict next tokens. If it ran under DCP, the draft tokens would be inconsistent across DCP ranks (each rank only sees 1/4 of the context).

Solution: the @dcp_disabled() context manager temporarily disables DCP for the draft model's forward pass. The draft model uses a separate, non-sharded KV pool with draft_pool_token_multiplier = dcp_size (4×) to allocate enough capacity for the full sequence. After draft generation, the target model verifies draft tokens under DCP mode—each DCP rank independently verifies its 1/N_dcp shard of the draft tokens, then all-gather merges the acceptance results.

# eagle_worker_v2.py @dcp_disabled() # temporarily disable DCP for draft model function forward_draft(...): # draft model sees full sequence, not affected by DCP sharding # target model verifies draft tokens under DCP mode ... # draft pool token allocation accounts for DCP multiplier draft_pool_token_multiplier ← server_args.dcp_size # 4×
